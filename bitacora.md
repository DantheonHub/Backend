# Bitácora de clases — Backend

Registro breve de cada clase, en el orden real en que se dieron. Sin fechas de calendario (quedan en el historial de commits). Nivel de detalle técnico: ver `conceptos.md`.

- **Clase 01 — Git Init:** Presentación de la materia y del programa. Instalación de programas (VS Code, Node.js, Git). Introducción a los Sistemas de Control de Versiones: qué son, tipos (locales, centralizados, distribuidos) y ejemplos. Introducción a Git y sus conceptos clave (repositorio, ramas, HEAD, origin), áreas de trabajo, estados de los archivos y comandos básicos. Introducción a GitFlow y a `.gitignore`.

- **Clase 02:** Repaso de la clase anterior (working directory, staging, repositorio local/remoto, fetch vs. pull, .gitignore, GitFlow). Generación y registro de claves SSH en GitHub. Demostración práctica en consola: `git init`, creación de ramas (`main`, `develop`, `uat`), diferencia entre merge, squash y rebase. Creación de un repositorio remoto en GitHub, clonado por SSH, gestión de colaboradores. Manejo de archivos: `git add`, `git status`, `git restore`, `git stash`. Configuración de reglas de protección de ramas y Pull Requests en GitHub. Introducción a la extensión Git Graph de VS Code.

  **Logística y evaluación de la cursada** *(no es contenido técnico del temario, es dinámica de la materia)*
  - **Proyecto integrador (grupal):** cada integrante tiene que generar sus propias ramas, commits y subidas — no vale que una sola persona centralice todo el trabajo del grupo. El profesor va a revisar el historial de commits de cada rama para evaluar la participación individual dentro del trabajo grupal, así que la prolijidad en los commits (mensajes claros, no subir archivos innecesarios) también cuenta para la evaluación.
  - **Entregas:** los repositorios de entrega tienen que estar en público (no hace falta agregar al profesor como colaborador) y se comparte el link — así se puede acceder y revisar sin gestionar permisos.
  - **Consultas entre clases:** el grupo de Telegram de la cursada es el canal recomendado para dudas fuera del horario de clase.

- **Clase 03:** Resolución de dudas de Git (diferencias entre `git stash pop/apply/drop/clear`, resolución de conflictos de merge en consola y VS Code, `git merge --abort`, creación de Pull Requests con reviewer y etiquetas). Cierre de Unidad 1 e inicio de **Unidad 2 (JavaScript):** tipos de lenguajes de programación, scripting, EcmaScript y motores de JS, TypeScript, variables (`var`/`let`/`const`), tipado dinámico, tipos de datos, condicionales, objetos y tipos de funciones (declaración, expresión, anónima, arrow, parámetro vs. argumento).

  **Logística de la cursada:** el viernes hay clase sincrónica compartida con la comisión de Frontend, como repaso de JavaScript para quienes cursan ambas materias.

- **Clase 04:** Repaso en profundidad de tipos de función (declaración, expresión, anónima/lambda, arrow) con ejemplos en vivo. Template literals (backticks). Operadores de comparación `==` vs `===`, y la diferencia entre `null` y `undefined` (incluyendo la rareza de `typeof null`). Introducción práctica a callbacks con una función calculadora que recibe distintas operaciones como argumento.

- **Clase 05:** Introducción a objetos (sintaxis, propiedades, mutabilidad aun siendo `const`) y profundización del comportamiento de paso por referencia vs. paso por valor, con demostración en vivo de cadenas de referencias entre objetos, comparación con `===` y los conceptos de inmutabilidad y *race condition* (con preview del operador *spread*, a desarrollar más adelante). Profundización de funciones: concepto de firma de una función (y su relación con TypeScript), función de orden superior, y de funciones callback — regla de invocación obligatoria, callback como último parámetro, múltiples callbacks y orden de ejecución, con varios ejemplos en vivo. No se llegó a ver Arrays (queda pendiente para la clase siguiente).

- **Clase 06:** Clase teórica (con diapositivas, sin código en vivo — queda para la clase siguiente) sobre Arrays: qué son, diferencia entre elemento e índice, arrays fuertemente tipados vs. la flexibilidad de JavaScript (y por qué mezclar tipos en un array es mala práctica aunque el lenguaje lo permita), formas de crear un array (literal y con `new Array()`), y el hecho de que los arrays son objetos (con repaso del patrón general objeto-punto-propiedad, usando también `console` y `JSON` como ejemplos de objetos ya incorporados en JavaScript). Métodos de array que modifican el original (`push`, `pop`, `unshift`, `shift`) y métodos de iteración (`forEach`, `filter`, `map`), estos últimos usados para repasar en profundidad el concepto de función de orden superior visto la clase pasada. Introducción a los operadores lógicos `&&` y `||`, aplicados en el ejemplo de `filter`. Se aclaró que algunos de estos temas (función de orden superior, callback) ya se habían tocado en la clase compartida con Frontend.

- **Clase 07 (clase larga, 221 min):** Práctica en vivo de todo lo dado teóricamente sobre Arrays (creación, `push`, `pop`, `shift`, `unshift`, `forEach`, `map`, con demostraciones puntuales como el corrimiento de índices al hacer `shift`, y el comportamiento de `pop`/`shift` sobre un array vacío). Objetos con acciones guardadas como funciones flecha en sus propiedades (ejemplo del auto: arrancar/frenar/acelerar), con validación de parámetros mediante `if`/`else`. A partir de ahí, profundización de conceptos de JavaScript: alcance (*scope*) de una variable dentro de una función y su relación con el *garbage collector*, y concepto de veracidad (*truthy*/*falsy*). Cierre de la parte de JavaScript e inicio de una nueva unidad (Node.js): qué es Node (entorno de ejecución, no lenguaje ni framework, motor V8), sus características (*event-driven*, no bloqueante, single-thread, escalable, multiplataforma) y sus usos típicos, y una introducción a NPM (diferencia entre módulo, paquete y dependencia, `package.json`, `node_modules`). **La clase se cortó a mitad de Node.js/NPM — se retoma y completa el viernes.**

- **Clase 08:** Continuación y cierre de Node.js/NPM: tipos de módulos (incorporados, locales, externos) y tipos de dependencias (directas/producción, de desarrollo, opcionales), con ejemplo práctico del módulo incorporado `os`. El caso real del incidente de *left-pad* (2016) como ejemplo de por qué ser consciente de las dependencias que se agregan a un proyecto. Sistemas de módulos CommonJS vs. ES Modules (`require` vs. `import`, carga sincrónica vs. asincrónica, y su convivencia dentro de un mismo proyecto) — se aclaró que la sincronía/asincronía en profundidad se da más adelante. Práctica en vivo extensa con comandos de NPM (`install`, `uninstall`, `--save-dev`/`-D`, `-g`, `init`, `init -y`, scripts con `npm start`/`npm run`) y recorrida de la página de un paquete en npmjs.com (versiones, licencia, descargas, árbol de dependencias, usando Express como ejemplo). Cierre con la creación de un módulo local propio y su exportación con `module.exports`.

- **Clase 09 (clase larga, 214 min):** Repaso rápido de Node/NPM/módulos, seguido de práctica en vivo profundizando `module.exports` y `require`: importar solo una propiedad puntual con destructuring, exportar con un alias (nombre interno distinto al expuesto), el motivo por el que modularizar facilita el mantenimiento (un cambio en un solo lugar impacta en todos los que lo usan), y dos errores comunes (escribir `exports` sin `module.` por delante, y dejar ejecuciones sueltas — como un `console.log`— dentro de un archivo de módulo). A partir de ahí, teoría de sincronía/asincronía: pila y cola como estructuras de datos (LIFO vs. FIFO, con varios ejemplos cotidianos), el *call stack* en programación sincrónica (con ejemplos de invocaciones secuenciales y anidadas), y la *callback queue*/*event loop* en programación asincrónica (con el ejemplo detallado de `setTimeout` dentro de una función `main`). Módulo `timers` (`setTimeout`, `setInterval`/`clearInterval`, mención de `setImmediate`) y módulo `fs` (métodos sincrónicos vs. asincrónicos, patrón de callback "error primero"). Cierre con la introducción teórica a Promesas (qué son, sus tres estados, cómo se construyen con `new Promise` y se consumen con `.then`/`.catch`/`.finally`). **Quedó pendiente el ejercicio práctico de `setTimeout` y promesas — se retoma el viernes.**

- **Clase 10 (clase larga, 224 min):** Práctica en vivo extensa repasando todo lo visto de sincronía (call stack con invocaciones secuenciales y anidadas, usando el módulo local ya creado) y asincronía (`setTimeout`, `setInterval`, comparación en vivo de `setImmediate` vs. `setTimeout(0)` mostrando que el orden entre ambos no es determinista — el mismo código da resultados distintos en cada corrida). Implementación práctica completa de una promesa (el ejemplo de "ir a comprar la crema"): creación con `new Promise`, resolución condicional con `resolve`/`reject`, y consumo con funciones manejadoras nombradas pasadas a `.then`/`.catch`/`.finally`, confirmando que la propia promesa es asincrónica (el código posterior a su declaración se ejecuta antes de que se resuelva). **Quedó planteada la introducción a promesas encadenadas (múltiples promesas interactuando en secuencia) — se retoma en la clase siguiente.**

- **Clase 11 (109 min):** Práctica en vivo extensa profundizando promesas con un ejemplo de suma de dos números obtenidos de forma asincrónica: por qué no alcanza con adivinar un tiempo de espera con `setTimeout` para sincronizar datos asincrónicos (agrega latencia innecesaria o falla si se subestima el tiempo real), y el descubrimiento en vivo (con una técnica de depuración a base de `console.log` estratégicos) de que `resolve`/`reject` solo aceptan un único valor — pasarles dos como en `resolve(numero1, numero2)` hace que el segundo se pierda silenciosamente. Se resolvió combinando los valores antes de resolver la promesa. Repaso reforzado de parámetro vs. argumento aplicado a la callback del ejecutor. Cierre con una demostración en vivo de los tres estados de una promesa (pendiente, cumplida, rechazada) y su inmutabilidad una vez resuelta. **Quedaron pendientes promesas encadenadas — se retoman el martes.**

- **Clase 12 (clase larga, 242 min):** Promesas encadenadas/anidadas en profundidad, con el caso de validar stock antes de ejecutar una venta (dos operaciones asincrónicas donde la segunda depende del resultado de la primera): la regla de no olvidarse el `return` dentro del `.then` para poder encadenar la siguiente promesa, y un único `.catch` compartido para toda la cadena. Extendido en vivo con una tercera promesa encadenada (`imprimirFactura`). Introducción a `async`/`await` como azúcar sintáctico sobre las promesas: sintaxis (`async` en la función, `await` antes de cada llamada asincrónica), que `await` solo bloquea la función en la que está (no todo el programa), manejo de errores con `try`/`catch` en vez de `.catch` (con la observación de que una función `async` con `try`/`catch` "absorbe" el error salvo que se vuelva a lanzar desde el `catch`), y los tres errores más comunes (usar `await` sin declarar la función `async`, no envolver en `try`/`catch`, y encadenar `await` de forma innecesaria cuando las operaciones no dependen entre sí). Cierre con una introducción teórica a eventos (módulo `events`, `EventEmitter`, `.on`/`.emit`) — **solo teoría, sin código ni práctica; el profesor aclaró que no entra en el examen y se retoma con ejemplos en una próxima clase.**

- **Clase 13 (clase larga, 239 min):** Repaso inicial de modularización, dependencias y flujo de ramas Git; aclaración sobre el ciclo de vida de una feature branch y el uso de squash al integrar cambios. Inicio práctico del backend HTTP: arquitectura cliente-servidor, roles de cliente y servidor, ciclo request/response y protocolo HTTP. Implementación conceptual de un servidor con el módulo nativo `node:http` (`createServer`, objetos `req`/`res`, `listen`, host/IP y puerto) y paso a Express como framework de servidor. Instalación de Express y Nodemon, comparación de Nodemon con el modo nativo `node --watch`, y repaso/aplicación de `fs` para lectura de archivos. Repaso de JSON (`JSON.parse`/`JSON.stringify`) e introducción formal al destructuring de arrays y objetos, incluido su uso para importar propiedades de módulos. Desglose de URL y DNS, diferencia entre parámetros de ruta y query params, y routing básico en Express con `app.get`. Práctica completa levantando un servidor local en `127.0.0.1:3000`, observando respuestas desde DevTools/Network, trabajando con estados `200`/`201`/`404`/`304`, agregando rutas `/` y `/api`, y enviando archivos HTML con `fs` y `Content-Type`. **Quedó iniciado el trabajo real con servidores y Express; la anatomía detallada de request/response, encabezados y tipos de contenido se profundiza en clases siguientes.**

  > **Logística y evaluación:** se confirmó el **primer parcial para el 9 de octubre** y la implementación/entrega final del proyecto para el **10 de noviembre**. La guía de ejercicios de módulos, instalación/desinstalación de paquetes y promesas se señaló como práctica relevante para el parcial. El profesor indicó que subiría las diapositivas al aula.

- **Clase 14 (117 min):** Continuación práctica de Express y preparación para el primer parcial. Se retomó el servidor de la clase anterior y se creó un módulo local `src/lenguajes.js` con un objeto que contiene arrays de objetos para frontend y backend. Repaso aplicado de CommonJS: `module.exports`, `require`, diferencia entre agregar una propiedad a `module.exports` y escribir por error `module.export`, e inspección del objeto exportado como técnica de depuración. Construcción de endpoints `GET` para devolver datos: conversión manual con `JSON.stringify`, `Content-Type: application/json`, códigos de estado y posterior simplificación con `res.json`. Se enfatizó que el código de estado y el tipo de contenido deben ser congruentes con la respuesta. Se agregaron rutas específicas para colecciones de frontend/backend y una ruta parametrizada (`:lenguaje`) leyendo `req.params`, conectando por primera vez de forma explícita routing, entrada del cliente y consulta sobre datos en memoria. Integración con métodos de arrays: `filter` para devolver todas las coincidencias, comparación con `find` para obtener la primera, detección de resultados vacíos mediante `length`, respuesta `404` cuando no existe el lenguaje y normalización con `toLocaleLowerCase()` para búsquedas sin sensibilidad a mayúsculas/minúsculas. La práctica consolidó la cadena módulo de datos → ruta → `req.params` → búsqueda → respuesta JSON. Se mostró además qué ocurre cuando una ruta recibe la solicitud pero no envía ninguna respuesta: el cliente queda en estado pendiente. Durante la depuración aparecieron casos de ruta o puerto incorrectos, `404`, error interno `500` y exposición de detalles internos del servidor, usados para introducir la necesidad de un manejo de errores adecuado. **Los parámetros y este flujo de API quedan para repaso en la clase siguiente antes del parcial.**

  > **Logística y evaluación:** el profesor indicó que la próxima clase será de repaso antes del examen. Para el parcial **no se permite utilizar agentes de IA ni entregar código provisto por el repositorio de clase como solución propia**. Sí se permite consultar Internet y documentación técnica durante la parte práctica, incluyendo documentación como MDN/NPM y búsquedas de errores. La parte teórica será **multiple choice en papel** y la parte práctica requerirá escribir/resolver el código. Se recomendó usar el fin de semana para repasar y practicar el proyecto visto en clase.

- **Clase 15 (clase larga, 239 min):** Repaso integral previo al primer parcial, sin apertura de una unidad nueva. Se reconstruyó desde cero el flujo mínimo de un proyecto Express: `npm init`/`npm init -y`, revisión de `package.json`, instalación de Express como dependencia y Nodemon como dependencia de desarrollo, creación de `index.js`, `require("express")`, `express()`, definición de host/puerto y `app.listen`. Se reforzó el orden de argumentos de `listen` (puerto → host → callback) y una estrategia de diagnóstico por etapas: distinguir un servidor inaccesible/conexión rechazada de una respuesta de Express como `Cannot GET /...`, que confirma que el proceso está escuchando pero la ruta no existe. Se repasó `app.get(ruta, callback)`, la diferencia parámetro/argumento, callback vs. función de orden superior y el papel de `req`/`res`.

  La práctica continuó con `src/instituto.js`, construyendo un objeto con una propiedad `alumnos` que contiene un array de objetos. A partir de esa estructura se repasaron mutación de objetos declarados con `const`, lectura de propiedades inexistentes (`undefined`), funciones almacenadas como propiedades y CommonJS. Se compararon distintas formas válidas de exportar (`module.exports.propiedad = valor`, `module.exports = { ... }`, `module.exports = valor`), se mostró por qué `module.export` no es equivalente a `module.exports`, y se conectó la forma del valor exportado con la ruta de acceso utilizada después de `require`. También se practicó destructuring al importar una propiedad concreta de un módulo.

  El bloque asincrónico retomó promesas encadenadas con el proceso **validar correlativas → inscribir alumno**. Ambas operaciones simularon demora con `setTimeout`, retornaron promesas y se coordinaron mediante una tercera función `ejecutarInscripcion`. Se enfatizó nuevamente que una operación dependiente debe retornarse desde el `.then` para formar parte de la cadena y que la función coordinadora también debe retornar esa cadena. El cierre integró todo con una ruta `/alumnos/:nombre`: lectura mediante `req.params`, búsqueda del alumno con `find`, normalización de texto y llamada al proceso asincrónico. Quedó planteado como paso final validar el caso “alumno no encontrado” y responder `404` antes de ejecutar la inscripción.

  > **Logística y evaluación:** última clase de repaso antes del primer parcial. Se confirmó que **Git no entra en esta primera instancia** y que el bloque de cola/*event loop* tampoco forma parte del examen. Se señalaron como relevantes la estructura básica de un servidor Express, NPM/`package.json`, objetos/JSON, callbacks, destructuring de objetos aplicado a módulos, promesas encadenadas, parámetros de ruta y métodos de arrays. La teoría será de 10 preguntas *multiple choice* basadas principalmente en las diapositivas y lo trabajado en clase; teoría y práctica deben aprobarse. Para la práctica se permite consultar Internet/documentación técnica. La entrega debe realizarse comprimida **sin `node_modules` y conservando `package.json`**. La restricción sobre agentes de IA ya había quedado establecida en la clase anterior.

- **Clase 16 (clase larga, 225 min):** Primera clase posterior al primer parcial. La primera parte se dedicó a reconstruir y resolver el examen, tanto la teoría como la práctica, utilizando el ejercicio de alquiler de películas como repaso integrado. Se revisaron estructura de objetos/arrays, exportación e importación CommonJS, destructuring, `find` sobre identificadores, parámetros de ruta, creación del servidor Express, `app.listen`, endpoints `GET` y promesas encadenadas. La resolución reforzó que los valores obtenidos desde `req.params` llegan como texto y que debe cuidarse la compatibilidad de tipos al buscar identificadores. También se insistió en leer el enunciado completo, probar por etapas y utilizar la documentación permitida en vez de depender exclusivamente de memoria sintáctica.

  En la segunda parte comenzó una etapa nueva de la materia centrada en **APIs y arquitectura**. Se definió una API como una interfaz/contrato que permite la comunicación entre sistemas ocultando los detalles internos de implementación; se repasaron APIs internas/privadas, públicas, de socios y compuestas, aclarando que una API pública puede requerir autenticación, límites o pago. Se distinguió REST como estilo arquitectónico y no como protocolo, y se mencionaron otras alternativas como SOAP, GraphQL y RPC.

  Se profundizó formalmente HTTP mediante la anatomía de **request** y **response**: línea inicial, método/target/versión, headers, separación con el body, status line, códigos de estado y contenido. Se introdujeron los métodos `GET`, `POST`, `PUT`, `PATCH` y `DELETE` y su relación conceptual con operaciones sobre recursos. Se corrigió la distinción semántica entre `400 Bad Request` y `404 Not Found`. También se introdujo **middleware** en Express como funciones que participan del ciclo request/response con acceso a `req`, `res` y `next`, y se presentaron clientes HTTP de prueba como Postman y REST Client para construir requests con métodos, headers y bodies.

  El cierre introdujo **patrones de diseño vs. patrones de arquitectura**, repasando ejemplos de patrones de diseño (Factory, Singleton, Adapter, Builder) y desarrollando MVC como separación de Model, View y Controller. A partir de ese puente se presentó la arquitectura que se utilizará en Backend: **Router → Controller → Service → Repository → fuente de datos**. Se definió la responsabilidad de cada capa y la restricción de no saltearlas: el router delega en controller, el controller en service, el service en repository y solo el repository accede directamente a la fuente de datos. El objetivo es desacoplar HTTP, lógica de negocio y persistencia para facilitar mantenimiento, pruebas y cambios de tecnología de datos.

  > **Continuidad:** esta clase convierte el servidor Express monolítico de las clases anteriores en el punto de partida para una arquitectura mantenible. El próximo paso práctico queda orientado a implementar estas capas y continuar trabajando con los distintos métodos HTTP y la anatomía completa de request/response.
